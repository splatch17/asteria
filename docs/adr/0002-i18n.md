# ADR-0002 — Internationalisation dès le premier jour

- **Statut** : Accepté
- **Date** : 2026-09-30

## Contexte
Lancement en **français uniquement**, mais l'anglais et d'autres langues doivent pouvoir s'ajouter **sans refonte**.

## Décision
- **Aucun texte utilisateur en dur** dans le code : tout passe par des clés i18n (format **ICU MessageFormat** : pluriels, genres, nombres).
- Bibliothèque : `svelte-i18n` ou Paraglide (choix final dans le ticket d'init UI). Catalogues dans `packages/ui/locales/<lang>.json`.
- Contenu éditorial (guide, histoires, anecdotes) : un fichier par langue, `packages/content/<lang>/...`, mêmes identifiants d'objet.
- Noms astronomiques : les données portent des noms **multilingues** (`name: { fr, en, la, ... }`) ; les désignations scientifiques (HIP, HD, Bayer) ne se traduisent pas.
- Formats localisés via `Intl` (dates, nombres, unités) ; coordonnées en notation scientifique standard.
- Mise en page tolérante : textes jusqu'à +40 % plus longs (allemand), prévision RTL (arabe, hébreu) via propriétés CSS logiques (`margin-inline`, etc.).
- **Contrôle CI** : lint interdisant les chaînes littérales dans les composants + vérification que toute clé `fr` existe dans le catalogue de référence.

## Conséquences
Léger surcoût au départ ; ajouter une langue devient une tâche de traduction, sans modification de code.
